# Brandfolio

Веб-приложение для создания брендбуков: проект → описание бренда, логотипы, цвета, шрифты → шаблон оформления → примеры применения → PDF и переносимый архив `.brandfolio.zip`. Работает без учётной записи, данные хранятся в браузере на текущем устройстве.

> Статус: в разработке, этап 1 из 6 (модель данных, схемы, прототип PDF).

## Команды

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # typecheck + production build в dist/
npm test           # unit-тесты (Vitest)
npm run typecheck
```

## План реализации

1. Модель и runtime-схемы, технический прототип PDF. ✅
2. Хранение (Dexie/IndexedDB), CRUD проектов, безопасные ассеты, автосохранение, конфликт вкладок.
3. Редактор и все разделы на базовом шаблоне, общий `BrandbookViewModel`.
4. Шаблоны Studio и Contrast, макеты применения, полноэкранный просмотр, адаптивность.
5. Итоговый PDF с точным предпросмотром, ZIP export/import, токены.
6. Главная, демо-бренд FORMA, полировка, e2e-проверки.

## Технические решения

- **Стек**: React 19 + TypeScript strict + Vite, React Router, Tailwind CSS 4, Zustand, Dexie, Zod 4, fflate (ZIP с потоковой проверкой лимитов), Lucide, Vitest, Playwright.
- **Модель** (`src/domain`) не зависит от React, хранения и PDF. Документ проекта сериализуем: ассеты упоминаются по ID, Blob и Object URL в документ не попадают. Все ссылки на цвета и ассеты проверяются схемой (`findBrokenReferences`).
- **Миграции** (`src/domain/migrations.ts`): документ последовательно поднимается до текущей `schemaVersion`, затем валидируется. Версия новее поддерживаемой отклоняется с объяснением.
- **Контраст** считается по WCAG 2.x. Решение pass/fail принимается по точному коэффициенту; для отображения коэффициент усекается до двух знаков, чтобы 4.499 не показывалось как 4.5. Примечание к ТЗ: в формуле линеаризации sRGB показатель степени равен 2.4 (`((c+0.055)/1.055)^2.4`), как в WCAG; в тексте ТЗ указано `^2`, это опечатка.
- **Шрифты**: Manrope, Noto Sans, Noto Serif (документ) и JetBrains Mono (HEX и числа в интерфейсе). `scripts/build-fonts.py` берёт вариативные шрифты из github.com/google/fonts, делает статические начертания и оставляет Latin, Latin Extended, кириллицу и пунктуацию, включая `‘` (U+2018) для узбекской латиницы. react-pdf встраивает статические TTF, поэтому вариативные файлы не используются. В Manrope нет глифа `ʻ` (U+02BB); редактор об этом предупреждает.
- **PDF**: `@react-pdf/renderer` 4.9 на клиенте, шрифты регистрируются в контексте рендера. Размеры из интерфейса в px переводятся в pt как `px × 72 / 96`. Unitless `lineHeight` в react-pdf считается от `fontSize` самого `Text` (по умолчанию 18), а не от унаследованного, поэтому стили документа всегда задают их вместе. Английская расстановка переносов отключена, чтобы не ломать русские и узбекские слова.
- **SVG** — отдельная граница безопасности (`src/features/assets/svgSanitizer.ts`): файл разбирается DOMParser и пересобирается по allowlist элементов и атрибутов. Запрещены script, обработчики событий, foreignObject, внешние ссылки, CSS `url()` кроме внутренних `url(#id)`, DOCTYPE и сущности; ограничены размер (1 МиБ), число элементов (5000) и вложенность (64). Если файл использует неподдерживаемое (текст, фильтры, встроенные растры, `<style>`), он отклоняется с предложением загрузить PNG. В превью очищенный SVG показывается только через `<img src="blob:">`, в PDF — растровая копия 1600 px.

## Известные ограничения

- react-pdf 4.9 в браузере пишет в консоль `Buffer is not defined` для каждого изображения (проверка `Buffer.isBuffer` после успешной загрузки). На результат не влияет.

## Лицензии шрифтов

Все шрифты распространяются по SIL Open Font License 1.1; тексты лицензий лежат рядом с файлами в `public/fonts/*-OFL.txt`, источники и контрольные суммы — в `public/fonts/fonts.json`.
